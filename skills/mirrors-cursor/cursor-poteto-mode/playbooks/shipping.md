### Shipping

**You own what lands. Verify each PR independently, land only the verified run from the root, then leave the stack alone while it lands.**

1. **Resolve the forge and verify every PR independently.** Use `gh` by default. If the installed `origin` command resolves the repository, use `origin pr` for its PR operations. Never require Graphite. A verifier who did not write the PR exercises the real surface against base and head through the matching installed native control skill or driver. Record `PASS`, `PASS+NOTES`, or `FAIL` with the verified head SHA. Green CI and bot approval do not replace this verdict. If the surface or a required native capability is unavailable, record the precise gap and do not claim parity.
2. **Find the contiguous verified run from the bottom.** Start at the lowest unmerged PR and stop at the first PR without a passing independent verdict. Only the PRs below that ceiling form the landable run. A verified PR above an unverified dependency waits. A PR that neither holds nor needs the lower change may be moved to trunk and landed independently, but it needs a fresh verdict on that base.
3. **Check whether each verdict still covers its patch.** Record the verdict's head SHA, base SHA, and stable `git patch-id`. Before landing, compare the current patch-id. If behavior changed, rerun the affected verifier. If only tests, docs, or lint configuration changed, compare builds from the old verdict and current head and judge each difference; embedded commit SHAs may be noise, but report the evidence. A lane without build output must be rerun. Even when the patch verdict still applies, recheck current mergeability and CI. Never infer validity from matching commit messages or an old green check.
4. **Prepare only the bottom PR.** Fetch current trunk and rebase the lowest verified branch onto it when needed. Push that branch and retarget only that PR to trunk. Re-run the patch comparison and verification rules from step 3. Do not retarget or arm descendants before the bottom PR merges.
5. **Land one PR at a time.** Confirm the bottom PR is mergeable and its current checks pass, then squash-merge it through the resolved forge. Arm auto-merge only when the operator asked for it and the verdict covers the current head. Read the PR back after the command; it is landed only when the forge reports it merged with trunk as its base. A queued merge or requested auto-merge is not a merge.
6. **Recompute after every merge.** Fetch trunk, confirm the merged commit is present, remove that PR from the frozen bottom-to-top list, and inspect the next PR's base, head, checks, and patch-id. The host may retarget a child automatically; verify rather than assume. Repeat steps 3 through 5 for that PR. Keep independent PRs outside the chain.
7. **Watch only the current frontier.** Use the native forge's status and check-wait tools, then read the PR again after each wake. Ignore a readiness event until the forge confirms `mergedAt` or `MERGED`. Treat a closed unmerged PR, a blocking required-check failure, or a dirty merge state without pending auto-merge as failure. Do not mutate the queue around the active frontier. Use a recurring Codex heartbeat only when the operator explicitly asked for recurring monitoring; otherwise continue the current task's bounded checks and report any cadence limit.
8. **Stop at the ceiling.** Report what landed, the next unverified PR, who produced each verdict, what was armed and how its state was confirmed, and the exact verification needed to extend the run.
