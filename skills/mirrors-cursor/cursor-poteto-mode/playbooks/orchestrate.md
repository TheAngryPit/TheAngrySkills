### Orchestrate

Run a standing program by assigning bounded work and checking its artifacts. A task one agent can finish within its session budget needs no program hierarchy. The coordinator owns scope, integration decisions and the user report; implementation belongs to its assigned owners.

Use advertised native collaboration and completion notifications. Keep state in the existing authorized project checkpoint and tracker. Do not assume a Cursor store, run an obsolete orch CLI, start polling loops, or relay status continuously. User-owned task creation, recurring monitoring, remote access, publication and merge remain separately covered by the user's actual authorization.

- One owner writes each PR branch. Only that owner pushes or changes topology. Independent tasks get separate bounded briefs and isolated writable outputs. Pass the exact goal, scope, dependencies, evidence and return channel; workers cannot assume sibling context.
- Use a sub-coordinator only where one coordinator cannot manage the area, retaining at most coordinator, track and worker levels. Respect actual concurrency and model-capability-router; do not invent cloud environments or model availability.
- Reuse a worker for a same-scope follow-up. Fork only when an advertised native mechanism can preserve required built state. Do not restart idle workers merely to ask status.
- Each PR needs a verifier distinct from its author. Prefer a supported different model family; if unavailable, disclose the missing independent perspective and preserve the workflow's required proof bar. Merge requires the actual authorization and verdict at the current head.
- Prove one unit end to end before expanding. Every kickoff names writable/excluded paths, forbidden actions and observable completion evidence.
- Inspect the artifact and diff, not only summaries or green CI. A verdict binds an exact SHA; changed code needs fresh relevant proof. Return drift to the owner and keep unrelated improvements optional.
- Verify live PR/check state before reporting. Account for each worker as complete, replaced or absorbed. Diagnose a stalled unit by evidence, bound retries by cause, and replan if it cannot finish. Do not invent a different model, host or provider to evade a refusal.
- Ask only for material unresolved decisions or real blockers. Continue authorized reversible work, retries and repairs without asking whether to continue.

Reply with outcomes against the goal, live PR links/states and verifier evidence, dropped work and reasons, and remaining user decisions. Preserve the checkpoint so a new session can resume.
