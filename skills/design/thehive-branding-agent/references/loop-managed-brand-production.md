# Loop-managed TheHive brand production

Use this reference for long-horizon TheHive brand, website, deck, Penpot, Open Design, campaign, or design-system work.

## Principle

All modes are loops.

A mode without a gate is just momentum.

Every loop has:

- trigger;
- source of truth;
- bounded work unit;
- proof surface;
- keep, repair, discard, or escalate decision;
- next loop condition.

## Project manager pattern

The Branding Agent acts as project manager and supervisor.

It should:

1. receive context and rambling from Vitor;
2. classify canon, reference, exploratory material and private source;
3. create one goal per real deliverable;
4. delegate narrow worker loops when useful;
5. keep a short checkpoint ledger in chat or file;
6. surface decision-ready briefs instead of raw outputs;
7. only commit, deploy, publish, send, or promote after explicit instruction or accepted gate.

## Standard loops

### Intake Loop

Trigger: new task, asset, deck, mockup, website request, source folder, packet, or context dump.

Work unit:

- read repo instructions;
- read relevant canon;
- inspect source assets;
- classify material as canon, reference, exploratory, private, stale, or conflict.

Gate:

- source list is explicit;
- conflicts are surfaced;
- public/private risk is classified.

### Canon Loop

Trigger: source material may affect TheHive architecture, naming, offers, public signal, or design system.

Work unit:

- compare against TheHive canon;
- preserve TheHiveMind, TheHiveGrid, TheHiveMap, TheHiveOS, TheHive Labs, TheHive Compute and idea constellation boundaries;
- reject stale names and generic AI agency framing;
- separate public-facing, internal, research and private layers.

Gate:

- claim is marked canon, recommendation, exploration, update, demote, reject, or needs Vitor/Echo decision.

### Visual Direction Loop

Trigger: website, deck, mockup, campaign, brandboard, image direction, design system, Penpot or Open Design task.

Work unit:

- choose the relevant design/taste skills;
- inspect approved references;
- define visual target and anti-slop risks;
- produce reviewable surface before claiming quality.

Gate:

- visual artifact or screenshot exists;
- deviations from approved references are named;
- accessibility, responsiveness, and text fit are checked when applicable.

### Source Reconstruction Loop

Trigger: recreate Illustrator, PDF, brandbook, layered source, deck, or approved asset inside Penpot/Open Design.

Work unit:

- source lock;
- tree read;
- mapping plan;
- one artboard, page, slide, or component at a time;
- visual and structural proof before advancing.

Gate:

- source unchanged proof exists;
- structure is human-reviewable;
- text remains text where required;
- names are semantic;
- no unresolved generic imports remain.

### Website Surface Loop

Trigger: TheHive website, Wix Studio, React/Vercel prototype, HTML review board, scroll narrative, offer surface, portfolio system.

Work unit:

- answer what TheHive is, what clients can buy now, why trust it, proof, and contact path;
- preserve future depth without explaining the whole universe;
- use Direction A as conversion spine, Direction C as v1 public route, Direction B as motion north star unless Vitor changes direction;
- classify ambitious interactions by implementation feasibility.

Gate:

- browser-visible surface exists;
- mobile or degraded behavior is considered;
- spectacle does not break clarity, performance, accessibility, or conversion.

### Delegation Loop

Trigger: a bounded subtask can be given to a worker without losing authority.

Allowed worker outputs:

- map;
- audit;
- comparison;
- list of issues;
- proposed patch;
- proof summary.

Not delegated:

- final canon decisions;
- public/private exposure decisions;
- destructive file operations;
- final visual acceptance;
- commit, push, publish, send, deploy or promotion.

Gate:

- supervisor reviews worker output against source and proof.

### Brief Loop

Trigger: human review needed.

Work unit:

- push the checkpoint as far right as safely possible;
- prepare a brief with what changed, why, link/path, proof, and exact decision needed.

Gate:

- Vitor can decide without reading raw logs.

## Keep, repair, discard, escalate

Each loop ends with one of:

- keep: gate passed and work advances;
- repair: fix bounded failures and re-run the gate;
- discard: wrong approach, remove or archive the failed result;
- escalate: human decision needed.

Do not continue through a failed gate.

## Proof wording

Use precise proof levels:

- implemented;
- code_proven;
- test_proven;
- runtime_proven;
- visually_checked;
- structure_checked;
- end_to_end_proven.

Do not call a visual preview "done" when structure, source, public safety, or canon gates are still open.
