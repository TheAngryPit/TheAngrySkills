# T3 execution contract

Read selection.md first. This contract applies only in a verified T3 host. Read method.md in full for the skill's existing workflow, rubrics, proof gates and conditional steps. That file is preserved methodology, expressed in the prior Codex vocabulary. For runtime-dependent instructions, apply the complete operation translations below instead of executing that vocabulary literally. No step is waived: an unmappable step is explicitly unsupported and keeps the workflow partial.

## Models and delegation

model-capability-router remains the operator policy. Read the exact advertised orchestrator_capabilities model/options. Retain an explicit provider/model/effort binding; report an unavailable choice without silently substituting, dropping options or adding a billing route. Do not write a competing model sheet or change the active thread's model.

An ordinary bounded child uses the host's permitted native same-provider tools only if the current T3 instructions allow its model, options and lifetime. Otherwise use delegate_task. Another provider, different model/settings, background execution or separate checkout uses delegate_task with a supported target. A separate checkout is isolation: "worktree"; never create it with shell commands or instructions in the task. Do not turn a worker into t3_thread_launch or create_threads. A new top-level thread needs an explicit user request. Cloud-only and unsupported separate-owner workflows remain partial rather than being silently reinterpreted as local work.

For an original named role, use the corresponding portable persona file listed in runtime-files.json next to this contract. Give the child its absolute persona path, the absolute SKILL.md path, immutable scope, relevant files/SHA, permitted actions, proof criteria and return shape. Tell it to read both before work. Preserve parent ownership and role-specific restrictions, including Comment Sicko's prohibition on application-code edits. This is instruction-persona delivery, not native named-agent registration. Missing persona or referenced skill is a named blocker. Do not replace a missing specialist with a generic role and claim equivalence. A child must not spawn more agents unless its task explicitly authorizes it.

Native Codex followup/reuse instructions in method.md map to a fresh delegate_task for a new review or re-check. Never use t3_thread_send to run a review round on childThreadId. Keep taskId; follow the returned next instruction and automatic completion notification. Do not poll a running delegate with task_status, sleeps, watchers or schedules. Read terminal results, then inspect the actual diff/artifacts before accepting the report. Use task_cancel to stop task-owned work no longer needed, never top-level interruption on a child.

## Work, state and proof

All named workflow steps, applied principle leaves, dependency checks, read-only/code ownership boundaries, source permissions, scope, full-candidate review and verification gates in method.md remain required. A brief that restricts writes is not a read-only runtime permission guarantee. Inherit native approval settings; never raise them, trust a hook or evade a refusal.

History means authorized T3 thread discovery/read, not guessed filesystem transcript paths. Read a named thread before answering about it. Native file-history operations requiring explicit paths remain unsupported until those paths are authorized; do not convert a history request into unrestricted thread enumeration. Retain no private transcript in public proof artifacts.

Keep the project's verification contract and proof-orchestrator. Browser, native desktop and device surfaces have different tools. Use preview tools only when permitted by the current host/user browser-work boundary; use native app/device tools for the surfaces they support. Do not turn every UI check into preview_* or an HTML mock. A build or metadata response is not runtime proof.

## PR and scheduling lifecycle

After creating, taking over or pushing a PR, the next call is link_pull_request for every layer with its full URL. Registering a PR is not proof of checks or approval. The owning thread uses watch_pull_request when asked to monitor or while an authorized PR action still waits on checks/reviews. Follow its continuation instruction. A delegated child never watches. Before handoff call unwatch_pull_request. Use no second polling loop, CLI watcher, schedule or heartbeat for PR events.

A time-based automation requires explicit task authorization and schedule_task. Installing this pack or invoking an ordinary skill creates no timer, sticky mode or future invocation. Existing user automations, scope and merge ownership are unchanged. An originally cloud/scheduled step that cannot run under the host contract remains an explicit gap.

Merge, close, publication, force push, production access and data removal remain subject to the operator's request and native controls. End with proof by operation, actual outcome and every incomplete or unsupported branch; do not certify a whole provider or playbook from one fixture.
