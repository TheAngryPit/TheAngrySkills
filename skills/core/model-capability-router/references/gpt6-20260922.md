# GPT-6 routing evidence — 22 September 2026

## Decision

Use GPT-6 Sol medium for coordination and GPT-6 Luna high/xhigh/max for the existing bounded-worker roles when the actual native channel supports them. Keep Astra low for planning and difficult judgment, with xhigh exceptional. This preserves the operator's working arrangement; it is not a benchmark-proven optimal allocation. Do not override an explicit selection or claim that installing this skill changes config.toml or running sessions.

## Official model documentation

| Model | Standard input / cached input / output, USD per million tokens | API reasoning |
|---|---|---|
| [GPT-6 Sol](https://developers.openai.com/api/docs/models/gpt-6-sol) | 2.00 / 0.20 / 10.00 | none, low, medium, high, xhigh, max |
| [GPT-6 Luna](https://developers.openai.com/api/docs/models/gpt-6-luna) | 0.10 / 0.01 / 0.50 | none, low, medium, high, xhigh, max |

Both pages advertise 1,050,000 context and 128,000 maximum output tokens. They describe Sol for complex coding/agentic workflows and Luna for focused high-volume work. Both document cache writes at 1.25x input and increased full-request rates above 272K input tokens: 2x input/cache and 1.5x output. Processing-mode and regional multipliers also apply. These are API prices, not Codex allowance measurements.

The native tool definitions in the reviewing session advertise GPT-6 Sol at low/medium/high/xhigh/max/ultra and GPT-6 Luna at low/medium/high/xhigh/max. API effort support is not interchangeable with native channel support. An advertised option does not by itself prove a successful authenticated run on every host.

Compared with the current published [Sol 5.6](https://developers.openai.com/api/docs/models/gpt-5.6-sol) rates (4 / 0.40 / 20), Sol 6 halves these token rates. Compared with [Luna 5.6](https://developers.openai.com/api/docs/models/gpt-5.6-luna) (0.20 / 0.02 / 1.20), Luna 6 halves input/cache rates and reduces output rates by about 58%. This does not establish the same reduction per completed task or in allowance.

## Launch evaluations and caching

The [OpenAI launch article](https://openai.com/index/introducing-gpt-6-sol-and-luna/) was read in the Browser, including accessible chart values. These are vendor-reported evaluations, not measurements of this Codex setup. Selected score / cost-per-task pairs:

|---|---|---|
| Sol 5.6 medium | 19.6% / $0.42 | 52.1% / $3.41 |
| Sol 6 medium | 26.9% / $0.21 | 53.1% / $1.27 |
| Sol 6 xhigh | 33.2% / $0.27 | 55.4% / $1.67 |
| Luna 6 high | 14.5% / $0.021 | 43.6% / $0.11 |
| Luna 6 xhigh | 12.6% / $0.025 | 47.9% / $0.11 |
| Luna 6 max | 20.7% / $0.037 | 50.9% / $0.15 |
| Astra low | 30.3% / $1.08 | 53.4% / $3.07 |

Sol medium supports retaining economical coordination. Luna effort results vary by workload: high exceeds xhigh on AutomationBench, while xhigh leads on Agents' Last Exam. More effort is not guaranteed to improve results. Sol xhigh is a plausible task-specific option, not a mandatory escalation stage or a reason to discard Astra judgment.

The launch article reports DeepSWE v1.1 results of 68.8% for Sol 6 max and 66.6% for Luna 6 max. Preserve their vendor provenance and effort labels; do not combine them with a different leaderboard run as a controlled comparison.

OpenAI documents that GPT-6 reasoning-effort changes and enabling/disabling tools preserve earlier context for cache reuse. See [reasoning changes](https://developers.openai.com/api/docs/guides/reasoning#change-reasoning-mid-conversation) and [prompt caching](https://developers.openai.com/api/docs/guides/prompt-caching#how-to-optimize-prompt-caching). Do not keep an unsuitable effort solely to avoid a presumed cache break. This does not establish cache sharing across models or tasks, guaranteed cache hits, or Codex allowance savings.

The detailed reasoning guide narrows this mechanism: `configuration_update`
changes effort between responses in GPT-6 standard single-agent API mode,
while request-level effort stays unchanged. It is not a model-switching item.
It has restrictions around adjacent updates and automatic compaction/truncation.
Do not inject it into Codex history or add invented TOML flags. Native client
support must be established separately.

[Codex CLI documents `/model`](https://learn.chatgpt.com/docs/cli/slash-commands#set-the-active-model-with-model)
for changing the selected model and supported effort in a session. The reviewing
app's task-message tool also exposes per-follow-up model/effort overrides. Its
subagent follow-up tool has no such override; reusing an agent does not by itself
change that agent's model. No self-switching tool was exposed to the parent.

## Independent benchmarks

An initial Browser inspection of AA and DeepSWE model selectors lacked the new models. The operator subsequently supplied [Artificial Analysis's launch thread](https://x.com/ArtificialAnlys/status/2102462962758033624), read in full in the Browser; it supersedes the earlier AA evidence gap.

AA reports these **max-effort** results:

| Metric | Sol 5.6 → 6 | Luna 5.6 → 6 |
|---|---|---|
| Intelligence Index cost/task | $1.99 → $1.06 | $0.18 → $0.07 |
| Output tokens/task | 29k → 31k | 41k → 51k |
| Coding Agent Index (Codex harness) | 55 → 57 | 43 → 41 |

All five chart images in the AA thread were inspected visually: general intelligence/cost, coding/cost, omniscience, GDPval, and the individual-evaluation grid. The coding cost plot places Sol high near xhigh with lower cost; treat this as a task-specific reason to consider high, not an exact numeric estimate from plotted coordinates or a mandatory escalation stage.

Sol 6 max's Coding Agent Index cost/task is $2.99. AA reports mixed evaluation changes and GDPval regressions for both models, with omitted requirements and weaker presentation among observed causes. These max-effort findings do not establish medium/high/xhigh performance. Keep the chosen default, but verify deliverable completeness and compare actual completed outcomes. AA's Codex-harness Luna DeepSWE result (64% versus 66%) must remain separate from OpenAI's reported 66.6% and the mini-swe-agent leaderboard.

DeepSWE's retrieved leaderboard is dated 22 September, v1.1, 113 tasks. It shows GPT-5.6 Sol max at 73% ±3%, average $6.46; GPT-5.6 Luna max at 67% ±4%, $0.61; and Astra xhigh at 74% ±3%, $4.43. These configurations use mini-swe-agent, not this Codex workflow. Do not relabel their scores as GPT-6 or compare those max rows with our medium/high profiles as if effort were controlled.

## What would justify changing the arrangement

Compare matched tasks using the actual model and effort, completion quality, interventions, total parent/worker usage, retries and elapsed time. A lower token price can coexist with more reasoning, verification or rework. Keep quality and cost claims provisional until those observations exist; no synthetic allowance conversion or automatic benchmark job is needed.

## Instruction design

Keep the router focused on selection and ownership. Leave task implementation to the agent and keep volatile evidence here, following the installed `writing-for-astra` skill and [OpenAI's instruction guidance](https://developers.openai.com/blog/rethinking-skills-and-prompts-for-gpt-6-astra). Preserve explicit verification and permissions without adding a compulsory model ladder.
