# TheMindShift Theme Approval Loop

Use this skill to turn active issue context, prior canon, and current external signal into reviewable theme options. Do not choose the final theme.

TheMindShift project files and `TheAngry_Editor-inChief` remain authority. This skill is procedural support for a repeated editorial loop.

## Required Reads

1. Read TheMindShift `AGENTS.md`, `ACTIVE_STATE.md`, `CHECKPOINTS.md`, `NEWSLETTER_DOCTRINE.md`, and the active issue folder.
2. Read the current lifecycle or format artifact if theme approval is blocked by lifecycle review.
3. Inspect any existing theme approval artifact before replacing it.

If the TheMindShift project root is missing, ask for it. Do not run this loop from memory alone.

## Loop Steps

1. Confirm the active issue number, current gate, and whether lifecycle review is closed enough to allow theme approval.
2. Collect theme candidates from project state, previous live canon, current external sources, and complicating or opposing evidence.
3. Produce five theme options with thesis, why now, source basis, risk, likely sections, and what Vitor would need to decide.
4. Self-review for one-sided source selection, generic AI commentary, stale assumptions, and drift from Vitor voice or positioning.
5. Revise the options if the self-review finds weak evidence, vague stakes, or unclear decision tradeoffs.
6. Hand back an HTML approval artifact target or artifact content, plus the recommended next action.

## Hard Stops

- Stop before final theme approval.
- Stop before publication, posting, emailing, contacting anyone, or changing external systems.
- Stop if external source access is needed but unavailable, and name the missing source need.

## Output

Return the artifact target, five theme options, evidence gaps, blocker status, and the exact Vitor decision needed.
