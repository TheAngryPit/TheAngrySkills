# Worktree cleanup

1. Snapshot and audit. Record disk capacity using the platform's native tools, then run `python3 scripts/cursor_worktree_audit.py <repo>` from this skill directory. It reads exact paths from Git and reports size, tracked/untracked work, cached merge and remote state. It never fetches, reads transcripts or deletes anything. Missing refs and unavailable usage evidence are unknown, never safe.
2. Check current PR states through the authorized forge tool. A closed but unmerged PR does not establish that work was preserved. Check every candidate against native Codex attachments, tasks and sessions, using their supported tools. Only read explicitly identified task transcripts within the authorized workspace boundary. If that evidence is unavailable, keep the candidate on hold. Do not scan all Codex homes for conversations.
3. Inspect tracked and untracked changes. Untracked files may be valuable work, not disposable scratch. Preserve concurrent work and stop only verified task-owned processes without remaining consumers. A clean worktree, merged commit or old timestamp alone does not prove it is unused.
4. Present exact candidates and evidence within the user's cleanup authority. For a Codex-managed worktree use native `archive_worktree` with the exact identity returned by `list_artifacts`; preserve any needed ignored files separately. Do not bypass refusal for pinned, primary or shared worktrees. For other directories, use the platform's recoverable Trash route after exact-target authorization. Never force-remove a worktree or permanently delete a directory by implication.
5. Verify archive/removal and retained work through the owning tools, then measure reclaimed disk capacity. Report held candidates and missing evidence. This playbook does not activate cleanup or monitoring by itself.
