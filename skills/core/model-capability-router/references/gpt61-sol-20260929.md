# GPT-6.1 Sol routing evidence — 29 September 2026

## Policy

Recommend `gpt-6.1-sol` at medium for sustained coordination, integration and
open-ended coding or agentic work when available to the account and client. This
is the selected shared policy, not a claim about the model active in a running
task. Preserve explicit native model and effort choices, including Sol low.
Keep Astra low for planning, consultation and difficult judgment, with xhigh
reserved for exceptional work. Keep Luna high/xhigh/max for bounded roles.
This policy adds no required model ladder, spending route or external action.

## Official Codex guidance

The [Codex models guide](https://developers.openai.com/codex/models) recommends
GPT-6.1 Sol for complex coding and agentic work when available to the account
and client, Luna for focused repeatable tasks, and Astra for the hardest
end-to-end work. It names `gpt-6.1-sol`. Availability and effort controls vary
by plan, client and workspace. This Codex guidance is distinct from API
reasoning-effort support and does not establish a host's current selection.

## API capability and pricing

The [GPT-6.1 Sol API model page](https://developers.openai.com/api/docs/models/gpt-6.1-sol)
lists API reasoning efforts `low`, `medium` (API default), `high`, `xhigh`
and `max`; `none` and `minimal` are unsupported. Use Responses for tool
calling; Chat Completions is supported without tool calling.

The published context window is 1,050,000 tokens with up to 128,000 output
tokens. That leaves up to 922,000 input tokens when reserving the full output
allowance (derived from those two published limits). The listed knowledge
cutoff is 30 April 2026.

| Standard API price per million tokens | USD |
|---|---:|
| Input | $2.00 |
| Cached input | $0.10 |
| Cache writes | $2.50 |
| Output | $10.00 |

Cache writes cost 1.25x uncached input. Requests with more than 272K input
tokens are charged at 2x input/cache and 1.5x output rates for the full
request. Fast mode costs 2x Standard; Batch and Flex cost half of Standard;
regional processing adds 10% where available. The page notes Fast mode is
unavailable with EU data residency.

OpenAI documents `configuration_update` for changing effort between responses
in standard single-agent GPT-6 API mode while preserving the original prompt
prefix for cache reuse. That API mechanism does not prove a Codex client supports
it. Do not retain an unsuitable effort based on assumed cache hits. API prices
are not Codex allowance measurements.

## Vendor-reported evaluations

The [GPT-6.1 Sol launch report](https://openai.com/index/introducing-gpt-6-1-sol/)
reports:

- DeepSWE v1.1: GPT-6.1 Sol matches GPT-6 Astra at roughly one-fifth the cost
  and beats GPT-6 Sol's best score by 6.4 percentage points at lower reasoning
  effort and cost.
- AutomationBench 1.0.6: at medium, GPT-6.1 Sol scores 4.8 points above GPT-6
  Sol at the same setting.
- OSWorld 2.0 offline set (v2026.08.08): at maximum effort, it scores 7 points
  above GPT-6 Sol and comes within 2.1 points of Astra.
- Terminal-Bench Science 0.1: Astra remains the highest-scoring tested model
  (68.1%) and is OpenAI's recommendation for the hardest scientific research.

These are OpenAI-reported evaluations. They support considering GPT-6.1 Sol for
the new coordination default while retaining Astra for the hardest judgment;
they do not guarantee quality or cost on this Codex workflow.

## Independent Artificial Analysis results

Artificial Analysis pages retrieved on 29 September 2026 report Intelligence
Index v4.3.2 results for GPT-6.1 Sol API configurations:

| Effort | Intelligence Index | Cost per task | Output tokens | Output speed |
|---|---:|---:|---:|---:|
| Low | 42 | $0.13 | 9M | 74.4 tokens/s |
| Medium | 48 | $0.21 | 15M | 62 tokens/s |
| High | 50 | $0.32 | 25M | 66.2 tokens/s |
| XHigh | 51 | $0.39 | 36M | 63.6 tokens/s |
| Max | 52 | $0.72 | 67M | 66.8 tokens/s |

Relative to low, medium gains 6 index points at about 62% higher benchmark
cost per task. Max gains 4 points over medium at about 3.4 times its benchmark
cost. These are benchmark-specific API measurements, not Codex allowance or
predictions of this operator's end-to-end task cost. They support medium as a
balanced policy for substantive coordination, leave low as a valid economical
explicit choice, and do not justify automatic max escalation.
