# Cursor plugin hooks to native Codex hooks: pinned-source crosswalk

Source: `cursor/plugins` commit `889ec4b68fa5aab0e867dad71ec3fdf386ae48f3`. The 27 plugin-level agent, hook, and rule files are pinned in `sources/cursor-plugins/manifest.json` under `support_files`. This report concerns the three families with upstream hooks. It does not activate any hook.

The local Codex CLI reports `hooks` as stable and enabled in `codex features list` (0.154.0). The [Codex hooks reference](https://developers.openai.com/codex/hooks) documents project-local `.codex/hooks.json`, exact-hash trust review, `PostToolUse`, `SubagentStop`, and `Stop`. Its `Stop` continuation response is `{"decision":"block","reason":"..."}`, whereas Cursor's hook expects `{"followup_message":"..."}`. A copied Cursor `hooks.json` is therefore not a native configuration.

| Family | Cursor event and condition | State and continuation | Native mapping to implement | Remaining proof |
| --- | --- | --- | --- | --- |
| `advisor` | `afterFileEdit` marks pending work; `afterAgentResponse` captures the last answer; `subagentStop` records a completed `advisor-subagent`; `stop` nudges after changed files when no consult happened, unless the answer ended in a question. | `.cursor/advisor/` state and log; one reminder per pending batch, Cursor `loop_limit: 3`. | `PostToolUse` can observe known edit tools, `SubagentStop` can read `agent_type` and `last_assistant_message`, and `Stop` can read `last_assistant_message` and continue with `decision: block`. | `continual-learning` | `stop` counts completed first-pass turns, requires a minimum turn count and elapsed minutes plus advanced transcript mtime; trial mode changes thresholds. | `.cursor/hooks/state/` counters and transcript index; follow-up requests an `agents-memory-updater` pass, which may edit `AGENTS.md`. | `Stop` exposes `turn_id`, `stop_hook_active`, and a possibly null `transcript_path`. The two `cursor-team-kit` rules and one `create-plugin` rule are plugin-level inputs. Their exact per-skill activation is unproven; they are recorded in the support ledger as package-scope relationships, not silently converted into Codex enforcement. The named agents can be bundled as bounded role references, as `cursor-no-comments` now does for `Comment Sicko`. Hooks require event-level adapters and native configuration before parity can be claimed.

## Isolated Codex payload fixture

`scripts/cursor_native_hook_adapters.py` accepts the documented `Stop` and `SubagentStop` JSON payloads. The synthetic CLI fixture in `tests/test_cursor_native_hooks.py` exercises an exact Ralph completion tag, maximum iteration, corrupt/cancelled state, duplicate turn ID, task/session and project isolation, advisor agent-ID correlation and verdict shape, and the question/no-nudge branch. It emits Codex's `decision: block`/`reason` for continuation. The fixture does not register a project hook, ask Codex to trust it, or establish that the host fires events with those payloads in a live task. The advisor edit marker (`PostToolUse`) and continual-learning thresholds are not ported yet. Concurrent turns and a host interruption still need proof before activation.
