# T3 transport for the existing model policy

This is no second model policy. Keep the operator's selected main model, role bindings, preset, effort and named specialists. Existing native Codex profile values and installation remain unchanged.

In an actual T3 context, inspect orchestrator_capabilities before the first delegate_task. The live catalog supplies providerInstanceId, model ID and supported options. The operator policy chooses a role; the transport maps that exact choice to target: {providerInstanceId, model, options}. Preserve boolean option types, explicit empty options and account-instance identity. A model's brand alone does not select its provider account.

There is no automatic fallback. If the selected provider, model, option, effort or required native specialist is unavailable, report that exact gap. Do not drop options, substitute another family, inherit a different model, change a persistent default or use a new billing route. A catalog recommendation is not configured state or proof of effective execution.

Use native same-provider delegation only where the current T3 host contract permits the child's model/options/lifetime. Different provider/model/settings or separate checkout uses delegate_task; separate checkout means isolation: "worktree". Tool-owned isolation replaces shell-created delegate worktrees. Do not create top-level threads as workers. Runtime approval refusals bind every route.

For a named specialist delivered through T3's generic role field, read the exact portable persona and include its absolute path, the parent-named SKILL.md, scope, allowed actions and proof contract in the child brief. Preserving the persona's behavior is separate from native agent_type registration. Read and verify its output; do not claim that its self-reported identity establishes the runtime selection.

Fresh review rounds use new delegate_task calls. Keep taskId, follow the returned next instruction and completion notifications, and cancel only the task-owned work no longer needed. Do not poll delegates or resume childThreadId for a new review. Cross-provider metadata and persona delivery do not grant credentials, spending, recursive delegation or publication.
