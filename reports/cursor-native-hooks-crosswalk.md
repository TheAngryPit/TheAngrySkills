# Cursor plugin hooks to native Codex hooks: pinned-source crosswalk

Source: `cursor/plugins` commit `889ec4b68fa5aab0e867dad71ec3fdf386ae48f3`. The 27 plugin-level agent, hook, and rule files are pinned in `sources/cursor-plugins/manifest.json` under `support_files`. This report concerns the three families with upstream hooks. It does not activate any hook.

The local Codex CLI reports `hooks` as stable and enabled in `codex features list` (0.154.0). The [Codex hooks reference](https://developers.openai.com/codex/hooks) documents project-local `.codex/hooks.json`, exact-hash trust review, `PostToolUse`, `SubagentStop`, and `Stop`. Its `Stop` continuation response is `{"decision":"block","reason":"..."}`, whereas Cursor's hook expects `{"followup_message":"..."}`. A copied Cursor `hooks.json` is therefore not a native configuration.

The two `cursor-team-kit` rules and one `create-plugin` rule are plugin-level inputs. Their exact per-skill activation is unproven; they are recorded in the support ledger as package-scope relationships, not silently converted into Codex enforcement. `cursor-no-comments` now routes to the public native `comment-sicko` profile asset, with no duplicate agent Markdown in the preview; fresh-session loading and selection are still unproven. Hooks require event-level adapters and native configuration before parity can be claimed.

## Isolated Codex payload fixture

`scripts/cursor_native_hook_adapters.py` accepts documented `PostToolUse`, `SubagentStop`, and `Stop` JSON payloads. Its hash is recorded under `native_support_files`, and the renderer bundles a byte-identical copy into the four related held candidates only. The synthetic CLI fixture in `tests/test_cursor_native_hooks.py` exercises Ralph's exact completion tag, maximum iteration, corrupt/cancelled state, duplicate turn ID, and task/project isolation. Advisor covers an `apply_patch` completion marker, tool-call deduplication, session isolation, expected agent ID and `advisor-subagent` type, verdict shape, question/no-nudge behavior, plus explicit task-bound enable/status/expected-agent/disable with no implicit model default. The fixture does not prove a live consult or that a named agent ID can be registered before the host's `SubagentStop` event. Continual-learning covers default 10-turn/120-minute and trial 3-turn/15-minute thresholds, transcript-root and mtime checks, duplicate turn, and unavailable transcript; it only stats transcript files and never reads their content. The project hook-state directory rejects symlinks in its managed path. The adapters emit Codex's `decision: block`/`reason` for continuation.

This fixture does not register a project hook, ask Codex to trust it, or establish that the host fires events with those payloads in a live task. Advisor currently observes only known `apply_patch` calls; Bash, MCP and out-of-band edits still need a proved change sensor. Continual-learning's source environment-variable threshold overrides and trial expiry are covered by synthetic events. A separate bounded role fixture updated only a synthetic `AGENTS.md` and index; it did not read a real transcript. Concurrent state writes, stale-index pruning, interrupted turns, and automatic host continuation still need proof before activation. No bundle has been enabled.
