# GPT-6.1 Terra routing evidence — 28 October 2026

## Adopted policy

The current operator profiles are defined in [SKILL.md](../SKILL.md). Terra uses
low for detection/identification, medium for visual interpretation, high for
difficult visual extraction, multistep computer use and professional tool work,
with justified xhigh and exceptional max. Sol, Astra, Luna, explicit selections
and fixed pstack specialist/preset bindings retain their existing roles.

This is an operator-approved routing choice informed by published results,
not a claim that a benchmark establishes the optimal effort for every task.
No local side-by-side model evaluation was run.

## API price and effort support

The [official model page](https://developers.openai.com/api/docs/models/gpt-6.1-terra)
lists none, low, medium, high, xhigh and max, with medium as the API default.
Standard API rates for prompts up to 272K input tokens are $1 per million input,
$0.05 cached input and $5 output tokens. Effort does not change these rates;
token use and latency change. Larger-context and processing-tier adjustments
still apply. API rates do not establish Codex allowance multipliers.

The [OpenAI launch charts](https://openai.com/index/introducing-gpt-6-1-terra/)
were read directly from their rendered chart points. Each cell is score percent
and estimated USD per task. These are vendor measurements, not independent
reproductions. Task versions, harnesses and metrics must remain attached.

| low | 83.7% / $0.0038 | 53.8% / $0.36 | 55.9% / $0.16 |
| medium | 84.6% / $0.0041 | 66.7% / $0.5 | 57.6% / $0.29 |
| high | 85.0% / $0.0045 | 68.7% / $0.51 | 57.2% / $0.39 |
| xhigh | 85.4% / $0.0055 | 71.3% / $0.62 | 58.5% / $0.66 |
| max | 85.5% / $0.012 | 74.2% / $1.19 | 60.0% / $1.01 |

The vision medium-over-low gain is 0.9 percentage points for about 8% more
estimated cost. OSWorld high gains 2 points over medium for about 2% more cost;
the launch charts do not provide per-effort end-to-end desktop timings. ALE
high is slightly below medium in this run; the general professional-work high
default is a policy tradeoff, not a claim that high wins every evaluation.
At OSWorld max, Terra scores 74.2% for $1.19 versus Sol max at 78.0% for $1.15;
raising Terra effort is not automatically preferable to choosing Sol.

## Independent vision effort comparison

[Roboflow Terra results](https://playground.roboflow.com/models/openai/gpt-6-1-terra)
and [methodology](https://playground.roboflow.com/evals). Each pair is low → high.

| Task | Score percent | Cost/sample USD | Seconds/sample |
|---|---:|---:|---:|
| detection | 84.7 → 84.7 | 0.0051 → 0.0081 | 14.45 → 21.49 |
| counting | 80.2 → 84.2 | 0.0018 → 0.0029 | 2.76 → 5.26 |
| identification | 96.9 → 96.9 | 0.0013 → 0.0014 | 1.84 → 2.10 |
| ocr | 81.9 → 84.4 | 0.0033 → 0.0066 | 11.45 → 18.75 |
| reasoning | 85.4 → 87.0 | 0.0016 → 0.0023 | 2.55 → 3.83 |

These are three-run means under the new protocol, with older rows being
re-run. OCR is a single preliminary run. Reported ± values are half-ranges,
not confidence intervals. Detection uses mAP@50; OCR is deterministic; counting,
identification and reasoning use an LLM judge against ground truth with strict
matching reported alongside. The aggregate uses equal weights and the low tier.
Roboflow does not publish medium/xhigh/max here or output tokens/s per task.

Low and high have the same displayed detection/identification scores. High
improves OCR by 2.5 points at twice the cost and about 1.64 times the latency;
the preliminary result supports a high option for demanding extraction, not
a universal claim about every transcription.

## Independent professional agent work

On [Mercor APEX-Agents v1.1](https://www.mercor.com/apex/apex-agents-leaderboard/),
the full live table displayed the following max configurations:

| Metric | Terra 6.1 max | Astra 6 max | Sol 6.1 max |
|---|---:|---:|---:|
| Pass@1 | 68.3% ±5.2 | 64.7% ±5.6 | 60.0% ±5.6 |
| Mean score | 79.3% ±4.1 | 75.1% ±4.6 | 73.2% ±4.6 |

The reported intervals overlap. APEX is long-horizon professional work across
applications, not an exclusively screenshot-driven GUI test. This snapshot
does not compare Terra efforts, so it cannot establish that max is necessary.

## Interpretation limits

Preserve the selected task model and native channel availability. Compare
quality, complete-task cost, time and rework on the actual workload. Neither
per-token price nor decoding speed alone establishes the best route. Do not
infer that detection accuracy proves reliable multi-step desktop completion,
or that a larger reasoning budget guarantees improvement.
